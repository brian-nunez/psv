Photosensitive epilepsy checker

A Go library, CLI and API server that finds hazardous flashing in video against WCAG 2.2 and broadcast guidelines.

Download v0.1.0 View on GitHub See the examples ↓
WCAG 2.2 · Success criterion 2.3.1
“Web pages do not contain anything that flashes more than three times in any one second period, or the flash is below the general flash and red flash thresholds.”

Three flashes are six alternating transitions. By default PSV fails a video at more than six in any one second, over at least a quarter of any 341×256 px region.

Quick start · macOS arm64Linux, macOS and Windows on amd64 and arm64 · needs ffmpeg and ffprobe on PATH

What it checks

Four standards, one detector

PSV finds general (luminance) flashes and red flashes, measures how much of the screen flashes together and how often, and reports a pass or fail verdict with the frames and screen regions involved.

ΔY is the change in relative luminance (0 to 1). On the 200 cd/m² display the broadcast guidelines assume, 0.1 is their 20 cd/m² threshold.

Benchmarked

Tested against the 346 videos of the Trace RERC PSE test media, built to sit just above or just below each threshold of each standard: 378 checks, 369 pass, 0 fail, and 9 are skipped because their listing entries contradict the thresholds they test.

Limits

PSV checks flashing, not every visual hazard. Regular spatial patterns such as stripes and checkerboards are a separate hazard and are not checked, and display brightness, HDR and viewing distance are not modelled.

Use it

Command line, API server or Go package

All three run the same core and produce the same psv.report/v1 report. The commands and Go code come from the README; output is from the v0.1.0 release binary.

1Command line

Check a video against WCAG 2.2. The exit status is 0 when it passes, 1 when it fails and 2 on an error, so psv can gate a build or upload pipeline.

Terminal
$ psv -format json -frames video.mp4 > report.json
$ psv render report.json > report.html      # a self-contained page of the report UI
$ psv render -open report.json              # write it to a temporary file and open it
$ psv -format json -frames video.mp4 | psv render -o report.html

psv render needs the per-frame results that -frames adds. Choose a standard with -standard: wcag22 (the default), trace24, broadcast or scene.

2API server

psv serve runs the API and the report UI at http://127.0.0.1:8080. It stores nothing: the video is the request body, the analysis streams back as newline-delimited JSON, and the upload is deleted when the request ends.

3Go package

github.com/brian-nunez/psv is one core package with only standard-library imports. AnalyzeFile decodes with FFmpeg; an Analyzer takes frames as they arrive.

Get the package

Terminal
$ go get github.com/brian-nunez/psv

Analyse a file

AnalyzeFile decodes the whole video and returns the complete analysis.

Go · main.go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/brian-nunez/psv"
)

func main() {
	ctx := context.Background()

	analysis, err := psv.AnalyzeFile(ctx, "video.mp4", psv.Options{})
	if err != nil {
		log.Fatal(err)
	}

	report := analysis.Report(false)
	fmt.Println(report.Verdict, report.Failures.Luminance, len(report.Defects))
}

Stream frames from a video

Probe and Decode read the video with FFmpeg, frame by frame, into an Analyzer. Unlike AnalyzeFile, you see each decision as it happens, about one second behind the frame being read, because whether a frame flashes depends on what follows.

Go · main.go
package main

import (
	"context"
	"errors"
	"fmt"
	"io"
	"log"
	"os"

	"github.com/brian-nunez/psv"
)

func main() {
	ctx := context.Background()
	path := os.Args[1]

	info, err := psv.Probe(ctx, path, psv.Tools{})
	if err != nil {
		log.Fatal(err)
	}

	dec, err := psv.Decode(ctx, path, info, psv.Tools{}, psv.DecodeOptions{})
	if err != nil {
		log.Fatal(err)
	}
	defer dec.Close()

	a, err := psv.NewAnalyzer(info.FrameRate.Float64(), info.Width, info.Height, psv.Config{Thresholds: psv.WCAG22()})
	if err != nil {
		log.Fatal(err)
	}

	read, failing := 0, false
	for {
		f, err := dec.Next() // valid until the next call
		if errors.Is(err, io.EOF) {
			break
		}
		if err != nil {
			log.Fatal(err)
		}
		read++

		n, err := a.Analyze(f) // n frames decided, about one second behind
		if err != nil {
			log.Fatal(err)
		}
		failing = warn(a.Analysis(), len(a.Analysis().Frames)-n, read, failing)
	}

	from := len(a.Analysis().Frames)
	analysis := a.Finish() // decides the last second
	warn(analysis, from, read, failing)

	verdict := analysis.Verdict()
	fmt.Println(verdict)
	if !verdict.Passed() {
		os.Exit(1)
	}
}

// warn prints a line when a run of failing frames starts in Frames[from:].
func warn(a *psv.Analysis, from, read int, failing bool) bool {
	for i := from; i < len(a.Frames); i++ {
		failed := a.Frames[i].Failed()
		if failed && !failing {
			fmt.Printf("warning: frame %d (%.2fs) fails WCAG 2.2, known after reading frame %d\n",
				i+1, a.FrameTime(i+1).Seconds(), read)
		}
		failing = failed
	}
	return failing
}

Analyse a live stream

Pipe raw frames from FFmpeg into the program, so any input FFmpeg reads works: a camera, an RTMP or RTSP stream, or a screen capture. The size and rate in the program match the scale and fps in the pipe.

Go · main.go
package main

import (
	"errors"
	"fmt"
	"io"
	"log"
	"os"

	"github.com/brian-nunez/psv"
)

// The size and rate FFmpeg is told to produce: -vf scale=1280:720,fps=30.
const (
	width  = 1280
	height = 720
	fps    = 30
)

func main() {
	a, err := psv.NewAnalyzer(fps, width, height, psv.Config{Thresholds: psv.WCAG22()})
	if err != nil {
		log.Fatal(err)
	}

	// Analyze samples the pixels before it returns, so one buffer is reused.
	buf := make([]byte, width*height*3)
	read, failing := 0, false
	for {
		if _, err := io.ReadFull(os.Stdin, buf); err != nil {
			if errors.Is(err, io.EOF) {
				break
			}
			log.Fatal(err)
		}
		read++

		n, err := a.Analyze(&psv.Frame{Width: width, Height: height, Pix: buf})
		if err != nil {
			log.Fatal(err)
		}
		failing = warn(a.Analysis(), len(a.Analysis().Frames)-n, read, failing)
	}

	from := len(a.Analysis().Frames)
	analysis := a.Finish()
	warn(analysis, from, read, failing)

	verdict := analysis.Verdict()
	fmt.Println(verdict)
	if !verdict.Passed() {
		os.Exit(1)
	}
}

// warn prints a line when a run of failing frames starts in Frames[from:].
func warn(a *psv.Analysis, from, read int, failing bool) bool {
	for i := from; i < len(a.Frames); i++ {
		failed := a.Frames[i].Failed()
		if failed && !failing {
			fmt.Printf("warning: frame %d (%.2fs) fails WCAG 2.2, known after reading frame %d\n",
				i+1, a.FrameTime(i+1).Seconds(), read)
		}
		failing = failed
	}
	return failing
}

What you can build
  • Your own thresholdsStart from WCAG22(), Trace24(), Broadcast() or SceneChange() and make them stricter.
  • Your own framesStream decoded frames from a screen recorder, game engine or camera, without FFmpeg.
  • Live warningsEach frame is decided about one second after it arrives.
  • Per-frame detailTransitions, area, the flashing region and a 64×36 mask for every frame.
  • A pipeline gateBranch on Verdict(), or use the CLI's exit status: 0 pass, 1 fail, 2 error.
  • The shared reportReport() writes psv.report/v1, the JSON the CLI, API and report UI all use.
